# План реализации: база проекта

План ведёт от пустого репозитория к работающему ядру расчёта. Основа — «Техническое задание v2» (дальше «ТЗ»). Каждый этап заканчивается проверкой «Готово, когда»: её надо выполнить командой, а не на глаз.

**Порядок этапов:**

1. Скелет проекта
2. Деньги и единицы
3. Настройки (модель)
4. Материал и масса
5. Операции
6. Калькулятор
7. Хранение
8. Импорт / экспорт
9. Интерфейс
10. Установщики

**База проекта** — этапы 1–6. После них вся логика расчёта работает и покрыта тестами, хотя окна ещё нет. Интерфейс строится в самом конце, поверх готового и проверенного ядра.

Почему такой порядок: ошибка в формуле цены стоит денег, а ошибка в цвете кнопки нет. Формулы проще всего проверять тестами, а тестам не нужен UI.

## 1. Скелет проекта

### 1.1. Структура

```
Slav/
├─ settings.gradle.kts        какие модули есть

├─ gradle/libs.versions.toml  все версии библиотек в одном месте
```

```
app  →  data  →  core
 └──────────────→ core
```

## 2. Деньги и единицы (`core`)

### 2.1. Почему не `Double`

```kotlin
println(0.1 + 0.2)   // 0.30000000000000004
```

В расчёте на 500 строк такие хвосты накапливаются, и итог расходится с калькулятором бухгалтера на копейку. Поэтому все деньги и размеры храним в `BigDecimal`.

**Ловушка BigDecimal:** `BigDecimal("2.0") == BigDecimal("2.00")` даёт **false**, потому что `equals` учитывает число знаков после запятой. Сравнивайте значения через `compareTo(...) == 0`. Это особенно важно в поиске по таблицам цен и в тестах.

### 2.2. Код

`core/src/main/kotlin/io/github/laalka/slav/core/Money.kt`:

```kotlin
package io.github.laalka.slav.core

import java.math.BigDecimal
import java.math.RoundingMode

@JvmInline
value class Money(val amount: BigDecimal) : Comparable<Money> {
    operator fun plus(other: Money) = Money(amount + other.amount)
    operator fun times(factor: BigDecimal) = Money(amount * factor)
    operator fun times(count: Int) = Money(amount * count.toBigDecimal())

    /** Rounds to kopecks, half-up (ТЗ, раздел 10). */
    fun rounded() = Money(amount.setScale(2, RoundingMode.HALF_UP))

    override fun compareTo(other: Money) = amount.compareTo(other.amount)

    companion object {
        val ZERO = Money(BigDecimal.ZERO)
    }
}

fun Iterable<Money>.sum(): Money = fold(Money.ZERO, Money::plus)
```

`value class` в рантайме — это обычный `BigDecimal`, без лишнего объекта. Зато компилятор не даст передать «цену» туда, где ждут «массу».

`Units.kt`:

```kotlin
package io.github.laalka.slav.core

import java.math.BigDecimal
import java.math.MathContext

val MC: MathContext = MathContext.DECIMAL64
val PI: BigDecimal = BigDecimal("3.14159265358979323846")

/** mm → m */
fun BigDecimal.mmToM(): BigDecimal = movePointLeft(3)
```

## 3. Настройки: модель (`core`)

Это классы из раздела 4 ТЗ. Они сериализуются в JSON и используются сразу в трёх местах: в настройках, в снимке цен и в файле экспорта.

### 3.1. BigDecimal в JSON

kotlinx.serialization сам не умеет `BigDecimal`. Пишем сериализатор, который пишет число **строкой**, чтобы не потерять точность:

```kotlin
object BigDecimalSerializer : KSerializer<BigDecimal> {
    override val descriptor = PrimitiveSerialDescriptor("BigDecimal", PrimitiveKind.STRING)
    override fun serialize(encoder: Encoder, value: BigDecimal) = encoder.encodeString(value.toPlainString())
    override fun deserialize(decoder: Decoder) = BigDecimal(decoder.decodeString())
}

typealias Decimal = @Serializable(with = BigDecimalSerializer::class) BigDecimal
```

Дальше во всех `@Serializable`-классах пишем `Decimal` вместо `BigDecimal`.

### 3.2. Справочники и цены

```kotlin
@Serializable
data class MaterialGroup(val name: String)

@Serializable
data class Grade(
    val name: String,             // «09Г2С»
    val group: String,            // имя группы: «Сталь»
    val densityKgM3: Decimal,     // 7850
    val pricePerKg: Decimal,      // ₽/кг
)

/** Одна ячейка таблицы «группа × толщина». */
@Serializable
data class ThicknessPrice(val group: String, val thickness: Decimal, val price: Decimal)

@Serializable
data class PriceBook(
    val formatVersion: Int = 1,
    val currency: String = "₽",
    val groups: List<MaterialGroup>,
    val grades: List<Grade>,
    val sortament: Sortament,
    val laserSheetPerM: List<ThicknessPrice>,
    val laserSheetPierce: List<ThicknessPrice>,
    val laserTubePerM: List<ThicknessPrice>,
    val laserTubePierce: List<ThicknessPrice>,
    val bending: List<BendPrice>,
    val bendRangesMm: List<Decimal>,      // границы: [500, 1500]
    val welding: List<WeldPrice>,
    val spotWelding: List<GroupPrice>,
)
```

**Почему таблица — это список ячеек, а не `Map<String, Map<BigDecimal, BigDecimal>>`.** Ключ `BigDecimal("2")` и ключ `BigDecimal("2.0")` в `Map` — это два разных ключа (см. 2.1). Пользователь ввёл «2,0», сортамент хранит «2», и цена «не найдена», хотя она есть. Список с поиском через `compareTo` такой ошибки не даёт:

```kotlin
fun List<ThicknessPrice>.find(group: String, t: BigDecimal): BigDecimal? =
    firstOrNull { it.group == group && it.thickness.compareTo(t) == 0 }?.price
```

**Ссылки по имени, а не по id.** Марка ссылается на группу по имени, таблицы цен тоже. Это то же правило, по которому в ТЗ работает слияние настроек (раздел 9). Цена такого решения: переименование группы должно обновлять все ссылки внутри `PriceBook`. Сделайте для этого одну функцию `PriceBook.renameGroup(old, new)` и тест к ней.

`PriceBook` целиком и есть **снимок цен** (ТЗ 8.4). При расчёте копия текущего `PriceBook` сохраняется вместе с расчётом. Так проще и надёжнее, чем вычислять, какие именно ячейки использовались.

### Готово, когда

Тест «PriceBook → JSON → PriceBook даёт равный объект» зелёный. Сравнивать нужно поля-числа через `compareTo`.

## 4. Материал и масса (`core`, ТЗ раздел 5)

`sealed interface` — это закрытый список вариантов. `when` по нему компилятор проверяет на полноту: добавите новый вид проката, и каждое место, где его забыли обработать, станет ошибкой компиляции.

```kotlin
@Serializable
sealed interface Material {
    val grade: String
    /** Толщина листа или стенки трубы; у уголка и швеллера — null. */
    val thickness: BigDecimal?

    @Serializable @SerialName("sheet")
    data class Sheet(override val grade: String, override val thickness: Decimal,
                     val lengthMm: Decimal, val widthMm: Decimal) : Material

    @Serializable @SerialName("round_tube")
    data class RoundTube(override val grade: String, val diameterMm: Decimal,
                         val wallMm: Decimal, val lengthMm: Decimal) : Material {
        override val thickness get() = wallMm
    }

    @Serializable @SerialName("profile_tube")
    data class ProfileTube(override val grade: String, val aMm: Decimal, val bMm: Decimal,
                           val wallMm: Decimal, val lengthMm: Decimal) : Material {
        override val thickness get() = wallMm
    }

    @Serializable @SerialName("rolled")
    data class Rolled(override val grade: String, val kind: RolledKind, val size: String,
                      val massPerMeterKg: Decimal, val lengthMm: Decimal) : Material {
        override val thickness: BigDecimal? get() = null
    }
}

enum class RolledKind { ANGLE, CHANNEL }
```

Масса (формулы из ТЗ 5). Размеры в мм, а 1 м³ = 10⁹ мм³, поэтому объём в мм³ сдвигаем на 9 знаков влево и получаем м³:

```kotlin
/** mm³ → m³, exact */
private fun BigDecimal.mm3ToM3(): BigDecimal = movePointLeft(9)

fun Material.massKg(density: BigDecimal): BigDecimal = when (this) {
    is Material.Sheet ->
        (lengthMm * widthMm * thickness).mm3ToM3() * density
    is Material.RoundTube ->
        (PI * (diameterMm - wallMm) * wallMm * lengthMm).mm3ToM3() * density
    is Material.ProfileTube ->
        ((BigDecimal(2) * (aMm + bMm) - BigDecimal(4) * wallMm) * wallMm * lengthMm).mm3ToM3() * density
    is Material.Rolled ->
        massPerMeterKg * lengthMm.mmToM()
}
```

> **Деление `BigDecimal` в Kotlin — ловушка.** Оператор `/` оставляет у результата масштаб левого числа. `BigDecimal("1000000") / BigDecimal("1E9")` даст **0**, а не 0.001: у левого числа нет знаков после запятой, и результат округлится до целого. Поэтому здесь используется `movePointLeft`, это точный сдвиг запятой. Там, где делить всё-таки нужно, пишите `a.divide(b, MC)`.

Тест с ручным расчётом. **Сначала считаете на бумаге, потом пишете тест.**

```kotlin
@Test
fun `sheet 1000x500x2 steel weighs 7_85 kg`() {
    val sheet = Material.Sheet("Ст3", BigDecimal("2"), BigDecimal("1000"), BigDecimal("500"))
    // 1000 × 500 × 2 = 1 000 000 мм³ = 0,001 м³ × 7850 = 7,85 кг
    assertEquals(0, BigDecimal("7.85").compareTo(sheet.massKg(BigDecimal("7850"))))
}
```

Сделайте по такому тесту на каждый вид проката. Для труб сверьте результат с табличной массой по ГОСТ: расхождение должно быть меньше 1–2 %.

Стоимость материала:

```kotlin
fun materialCost(material: Material, grade: Grade): Money =
    Money(material.massKg(grade.densityKgM3) * grade.pricePerKg)
```

### 5.2. Ошибки «нет цены» копятся, а не бросаются

По ТЗ 7.3 пользователь должен увидеть **все** недостающие цены сразу, а не по одной. Поэтому исключение не подходит: оно остановит расчёт на первой же ошибке.

```kotlin
sealed interface CalcError {
    data class MissingPrice(val table: String, val group: String, val column: String) : CalcError
    data class UnknownGrade(val name: String) : CalcError
    data class NotApplicable(val operation: String, val material: String) : CalcError
}

/** Сборщик ошибок: каждая функция цены пишет в него и возвращает ноль, если цены нет. */
class Errors {
    val list = mutableListOf<CalcError>()
    fun missing(table: String, group: String, column: String): BigDecimal {
        list += CalcError.MissingPrice(table, group, column)
        return BigDecimal.ZERO
    }
}
```

### 5.3. Пример: лазерный рез листа (ТЗ 6.2)

```kotlin
fun priceLaserSheet(op: OperationInput.LaserSheet, m: Material.Sheet, group: String,
                    book: PriceBook, err: Errors): Money {
    val (lengthMm, pierces) = when (val c = op.contour) {
        Contour.Rectangle -> BigDecimal(2) * (m.lengthMm + m.widthMm) to 1
        is Contour.Length -> c.lengthMm to c.pierces
    }
    val perM = book.laserSheetPerM.find(group, m.thickness)
        ?: err.missing("Лазер, лист ₽/м", group, m.thickness.toPlainString())
    val pierce = book.laserSheetPierce.find(group, m.thickness)
        ?: err.missing("Врезка, лист ₽/шт", group, m.thickness.toPlainString())
    return Money(lengthMm.mmToM() * perM + pierce * pierces.toBigDecimal())
}
```

## 6. Калькулятор (`core`, ТЗ разделы 3 и 10)

```kotlin
@Serializable
data class Part(val name: String, val qtyPerProduct: Int,
                val material: Material, val operations: List<OperationInput>)

@Serializable
data class CalculationInput(val name: String, val quantity: Int,
                            val parts: List<Part>, val productOperations: List<OperationInput>)

data class Line(val title: String, val cost: Money)            // строка разбивки, уже округлена
data class PartResult(val name: String, val massKg: BigDecimal, val lines: List<Line>) {
    val cost: Money get() = lines.map { it.cost }.sum()
}
data class CalcResult(val parts: List<PartResult>, val productLines: List<Line>,
                      val unitPrice: Money, val unitMassKg: BigDecimal)

sealed interface CalcOutcome {
    data class Ok(val result: CalcResult) : CalcOutcome
    data class Failed(val errors: List<CalcError>) : CalcOutcome
}

class Calculator(private val book: PriceBook) {
    fun calculate(input: CalculationInput): CalcOutcome { … }
}
```

Порядок внутри `calculate`:

1. Для каждой детали найти марку (если нет — `UnknownGrade`), посчитать массу и строку «Материал».
2. Для каждой операции детали посчитать строку и **сразу округлить её** (`rounded()`): так требует правило ТЗ 10.
3. `unitPrice = Σ (стоимость детали × qtyPerProduct) + Σ строк операций изделия`.
4. Если в `Errors` что-то есть, вернуть `Failed` со всеми ошибками. Иначе вернуть `Ok`.

Итог по тиражу в `CalcResult` не хранится. Это `unitPrice × quantity`, и ТЗ 8.2 разрешает менять тираж в карточке без пересчёта.

**«Пересчитать по текущим ценам»** — это `Calculator(currentBook).calculate(savedInput)`. **«Повторный расчёт после правки»** — это `Calculator(savedSnapshot).calculate(editedInput)`. Обе функции ТЗ сводятся к выбору, какой `PriceBook` передать.

### Главный тест: настоящий расчёт

Возьмите **реальный прошлый расчёт** с вашего производства: изделие из 2–3 деталей с лазером, гибкой и сваркой, где известна итоговая цена. Заполните `PriceBook` теми ценами, по которым тогда считали, и `CalculationInput` теми же параметрами. Тест должен выдать ту же сумму.

Если сумма не сходится, значит, в ТЗ неверна формула. Это лучшая проверка всей модели, и её лучше пройти сейчас, а не после того, как готов UI.

### 7.1. Схема: две таблицы плюс JSON

`data/src/main/sqldelight/io/github/laalka/slav/data/db/Slav.sq`:

```sql
CREATE TABLE settings (
    id INTEGER NOT NULL PRIMARY KEY CHECK (id = 1),   -- всегда одна строка
    json TEXT NOT NULL,                               -- PriceBook
    updated_at INTEGER NOT NULL
);

CREATE TABLE calculation (
    id TEXT NOT NULL PRIMARY KEY,            -- UUID
    name TEXT NOT NULL,
    name_search TEXT NOT NULL,               -- name.lowercase(), см. ниже
    status TEXT NOT NULL,                    -- DRAFT, CALCULATED, SENT, IN_WORK, ARCHIVED
    quantity INTEGER NOT NULL,
    unit_price TEXT,                         -- BigDecimal строкой; NULL у черновика
    updated_at INTEGER NOT NULL,
    input_json TEXT NOT NULL,                -- CalculationInput
    snapshot_json TEXT                       -- PriceBook на момент расчёта
);

listCalculations:
SELECT id, name, status, quantity, unit_price, updated_at
FROM calculation
WHERE name_search LIKE '%' || :query || '%'
ORDER BY updated_at DESC;
```

**Почему JSON, а не 15 нормализованных таблиц.** Деталь, операции, строки отверстий — это одно дерево, и читается оно всегда целиком. SQL нужен только для списка расчётов, поиска и фильтров, поэтому в колонки вынесено лишь то, что участвует в `WHERE` и `ORDER BY`. Добавление новой операции не потребует миграции базы.

**Почему колонка `name_search`.** В SQLite `LIKE` без учёта регистра работает **только для латиницы**: «Кронштейн» по запросу «кронштейн» не найдётся. Поэтому при сохранении пишите в `name_search` значение `name.lowercase()`, а запрос приводите к нижнему регистру в Kotlin.

### 7.2. Где лежит база (ТЗ 11)

```kotlin
fun appDataDir(): Path {
    val os = System.getProperty("os.name").lowercase()
    val base = when {
        "win" in os -> Path(System.getenv("APPDATA"))
        "mac" in os -> Path(System.getProperty("user.home"), "Library", "Application Support")
```

**Резервная копия при запуске:** копия `slav.db` в `backups/slav-<дата>.db`, хранятся последние 10.

## 8. Импорт и экспорт (`data`, ТЗ раздел 9)

Экспорт — это просто `Json.encodeToString(priceBook)` в файл. Импорт делается в три шага:

1. Прочитать файл. Если `formatVersion` больше нашего, выдать ошибку «обновите программу». Если меньше, мигрировать.
2. Посчитать изменения и показать сводку.
3. Применить после подтверждения пользователя. Перед полной заменой сделать резервную копию.

Слияние по имени — одна обобщённая функция для всех справочников:

```kotlin
data class MergeResult<T>(val merged: List<T>, val added: Int, val changed: Int, val kept: Int)

fun <T> mergeByName(local: List<T>, incoming: List<T>, name: (T) -> String): MergeResult<T> {
    fun key(t: T) = name(t).trim().lowercase()
    val incomingByKey = incoming.associateBy(::key)
    val localKeys = local.map(::key).toSet()

    var changed = 0
    val merged = local.map { l ->
        val i = incomingByKey[key(l)]
        if (i != null && i != l) changed++
        i ?: l
    } + incoming.filter { key(it) !in localKeys }

    val added = incoming.count { key(it) !in localKeys }
    return MergeResult(merged, added, changed, kept = local.size - incoming.count { key(it) in localKeys })
}
```

Для ячеек таблиц цен ключ составной: `"${group.lowercase()}|${thickness.stripTrailingZeros()}"`. Здесь `stripTrailingZeros()` обязателен, иначе «2» и «2.0» получат разные ключи (снова 2.1).

## 9. Интерфейс (`app`)

### 9.1. Каркас окна

Слева `NavigationRail` с разделами «Расчёты» и «Настройки», справа содержимое. Отдельная библиотека навигации для четырёх экранов не нужна. Иконка `Icons.Default.Calculate` лежит в расширенном наборе иконок, поэтому в `app` нужна зависимость `compose.materialIconsExtended` (или та же строка из проекта мастера):

```kotlin
sealed interface Screen {
    data object Calculations : Screen
    data class Editor(val id: String?) : Screen     // null — новый расчёт
    data class Card(val id: String) : Screen
    data object Settings : Screen
}

@Composable
fun App(deps: Deps) {
    var screen by remember { mutableStateOf<Screen>(Screen.Calculations) }
    Row {
        NavigationRail {
            NavigationRailItem(selected = screen !is Screen.Settings,
                onClick = { screen = Screen.Calculations },
                icon = { Icon(Icons.Default.Calculate, null) }, label = { Text("Расчёты") })
            NavigationRailItem(selected = screen is Screen.Settings,
                onClick = { screen = Screen.Settings },
                icon = { Icon(Icons.Default.Settings, null) }, label = { Text("Настройки") })
        }
        when (val s = screen) {
            Screen.Calculations -> CalculationListScreen(deps, onOpen = { screen = Screen.Card(it) },
                                                         onNew = { screen = Screen.Editor(null) })
            is Screen.Editor -> EditorScreen(deps, s.id, onCalculated = { screen = Screen.Card(it) })
            is Screen.Card -> CardScreen(deps, s.id)
            Screen.Settings -> SettingsScreen(deps)
        }
    }
}
```

`onCalculated = { screen = Screen.Card(it) }` — это требование ТЗ 7.1: после «Рассчитать» пользователь попадает в карточку расчёта.

### 9.2. Состояние экрана: модель + `StateFlow`

Composable-функция только рисует. Логика экрана живёт в обычном классе, который можно тестировать без окна:

```kotlin
data class ListState(val query: String = "", val items: List<CalculationRow> = emptyList())

class CalculationListModel(private val repo: CalculationRepository) {
    private val _state = MutableStateFlow(ListState())
    val state: StateFlow<ListState> = _state.asStateFlow()

    fun onQueryChange(q: String) {
        _state.update { it.copy(query = q, items = repo.list(q)) }
    }
}

@Composable
fun CalculationListScreen(model: CalculationListModel) {
    val state by model.state.collectAsState()
    Column {
        OutlinedTextField(state.query, model::onQueryChange, label = { Text("Поиск") })
        LazyColumn {
            items(state.items, key = { it.id }) { row -> CalculationRowItem(row) }
        }
    }
}
```

`Deps` — это «корень композиции»: один класс в `Main.kt`, где создаются драйвер, репозитории и модели. DI-библиотека на таком размере не нужна.

### 9.3. Как добиться современного вида

- Своя цветовая схема Material 3: `lightColorScheme(primary = …)` / `darkColorScheme(…)`, переключаемая по настройке.
- Отступы кратны 8 dp. Карточки `Card` / `ElevatedCard` с закруглением 12–16 dp.
- Числа в таблицах выравниваются по правому краю, моноширинными цифрами (`fontFeatureSettings = "tnum"`).
- Ошибки ввода показываются у самого поля (`isError` + `supportingText`), а не в диалоге.

### Порядок экранов

1. Настройки: без них не из чего считать.
2. Редактор расчёта с черновиком.
3. Список.
4. Карточка.
5. Экспорт PDF (Apache PDFBox) и Excel (Apache POI).

## 10. Установщики (ТЗ 1.2)

```bash
./gradlew :app:packageMsi   # только на Windows
./gradlew :app:packageDmg   # только на macOS
```

`jpackage` не умеет собирать установщик под чужую ОС. Отсюда два варианта: собирать `.msi` на Windows-машине или поручить это CI (GitHub Actions с `runs-on: [windows-latest, macos-latest]`).

Обязательно задайте в блоке `windows { }`:

```kotlin
windows {
    upgradeUuid = "СГЕНЕРИРУЙТЕ-ОДИН-РАЗ-И-НЕ-МЕНЯЙТЕ"   // uuidgen
    menuGroup = "Slav"
    perUserInstall = true
}
```

Без постоянного `upgradeUuid` каждая новая версия `.msi` встанет **рядом** со старой, а не поверх неё. `packageVersion` должен иметь вид `MAJOR.MINOR.BUILD`, где MAJOR > 0, иначе сборка `.dmg` откажется работать.

## Сводка ловушек

| Ловушка | Где укусит | Защита |
|---|---|---|
| `Double` для денег | итог расходится на копейки | только `BigDecimal` (2.1) |
| `BigDecimal.equals` учитывает масштаб | «цена не найдена», тесты | `compareTo`, `stripTrailingZeros` (2.1, 3.2) |
| Деление `BigDecimal` через `/` | `1000000 / 1E9 = 0` | `movePointLeft`, `divide(x, MC)` (4) |
| `LIKE` в SQLite и кириллица | поиск не находит | колонка `name_search` (7.1) |
| Исключение на первой недостающей цене | пользователь чинит цены по одной | сборщик `Errors` (5.2) |
| Хранить вычисляемое (глубина) | рассинхрон с толщиной | вычислять при показе (5.1) |
| Нет `upgradeUuid` | версии ставятся параллельно | постоянный UUID (10) |
